# P1-009 evidence: control_guard scheduling and seven-day delay

- Date: 2026-09-19 (last updated 2026-09-21)
- Scope: `crates/control-guard/src/lib.rs`, `crates/db/src/{schema,repo}/guard.rs`
- Check: `bash scripts/pocket-ic-test.sh --test guard_upgrade` (**five passes**)

## Checks performed

| Test | Behavior | Coverage |
|---|---|---|
| `only_the_sns_principal_can_schedule` | Scheduling denied without SNS principal; controllers can set it; non-SNS scheduling rejected; admitted `executable_at = scheduled_at + seven days` | T-501 |
| `execution_is_blocked_until_seven_days_and_on_content_mismatch` | Reject before seven days with `UpgradeTooEarly`; reject mismatched Wasm with `UpgradeContentMismatch`; **actually execute `install_code`** after seven days for a match; remove reservation and reject duplicate execution | T-502, T-503, T-504 |

## Implementation details

- Reservations store only `target`, `wasm_hash`, `arg_hash`, `scheduled_at`, and `executable_at`, with no customer data.
- Authorization happens outside transactions and rejects non-SNS scheduling/cancellation.
- No APIs for arbitrary management calls, controller changes, reinstall, stop, delete, or shortening the delay.

## Additional execution and concurrency checks

| Test | Behavior |
|---|---|
| `a_matching_reservation_executes_the_upgrade` | **Actually execute `install_code`** with minimal valid Wasm (eight-byte header), remove reservation, and reject duplicates |
| `only_one_concurrent_execution_wins` | Concurrent execution requests have **one successful executor**; the other is rejected through the `executing` CAS |

`claim_upgrade` CASes to `executing` before `install_code`, preventing duplicate installation. Since `install_code` awaits, both executions could pass without this claim; the test detected that behavior.

## Finding: execute_upgrade cannot send Wasm above 2 MiB in one ingress

`execute_upgrade(target, wasm_module, arg)` receives Wasm as an argument, but ingress is limited to 2,097,152 bytes. Measured `policy.wasm` grew to 2,193,336 bytes after dependencies were added. **Real-sized Wasm such as policy.wasm cannot be sent in one ingress.** The execution path is verified with minimal valid Wasm, but production needs chunked installation such as `install_chunked_code` or retrieval from a code registry. This requires design revision; real-Wasm execution remains unverified.

## Initial failure cause

The initial execution failure was in the test, not the guard: reserved `arg_hash` was `[0u8;32]`, not the SHA-256 of the actual empty argument. Aligning scheduled and executed arguments allowed execution verification.

## Unverified work for the next round

- Empty guard controllers (production target) and controller removal require separate Phase 4 approval.
