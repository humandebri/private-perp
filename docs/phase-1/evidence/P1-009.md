# P1-009 証跡：control_guardの予約と7日猶予

- 日付：2026-09-19
- 対象：`crates/control-guard/src/lib.rs`、`crates/db/src/{schema,repo}/guard.rs`
- 検証：`bash scripts/pocket-ic-test.sh --test guard_upgrade`（3件成功）

## 実行済みの検証

| 試験 | 内容 | 対応 |
|---|---|---|
| `only_the_sns_principal_can_schedule` | SNS principal未設定では予約不可、controllerが設定可能、非SNSからの予約を拒否、受理時は`executable_at = scheduled_at + 7日` | T-501 |
| `execution_is_blocked_until_seven_days_and_on_content_mismatch` | 7日未満の実行を`UpgradeTooEarly`で拒否、内容（wasm）不一致を`UpgradeContentMismatch`で拒否、予約は保持 | T-502、T-503、T-504 |
| `cancelling_starts_a_new_seven_day_window` | 取消はSNSのみ、取消後の新規予約は新しい7日を開始し、取消前の猶予を引き継がない | T-506 |

## 実装上の要点

- 予約は`target`・`wasm_hash`・`arg_hash`・`scheduled_at`・`executable_at`のみを保存し、顧客情報を持たない。
- 認可判定はトランザクションの外で行い、SNS principal以外の予約・取消を拒否する。
- 任意management call・controller変更・reinstall・stop・delete・猶予短縮のAPIは設けていない。

## 未検証（次ラウンド）

- **一致する予約の実際の実行（`install_code`）**：この経路は現在失敗するため、テストは内容不一致の拒否までで止めている。原因を特定して実行の試験を追加するまで、guardの実行経路は未検証として扱う。
- controller変更・reinstall・stop・deleteによる迂回拒否（API不在の確認はレビューで行う）、SNS自体のupgrade後の猶予維持。
