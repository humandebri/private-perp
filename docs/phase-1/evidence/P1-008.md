# P1-008 証跡：trading_coreの認可境界と注文受付

- 日付：2026-09-19（最終更新：2026-09-21）
- 対象：`crates/trading-core/src/lib.rs`、`crates/db/src/repo/{core_config,core_requests,meta,orders}.rs`
- 検証：`bash scripts/pocket-ic-test.sh --test core_auth --test core_orders`（**12件成功**。`core_auth.rs` 1件、`core_orders.rs` 11件）

## 実行済みの検証

| 試験 | 内容 |
|---|---|
| `core_auth.rs` | controllerがvault principalを設定、`whoami`がvaultの`session_status`で検証し、返却principalが呼び出し元と一致する場合だけuser_idを返す。別principal・失効セッション・非controllerの設定を拒否 |
| `core_orders.rs` | 認可後に注文を受付（metaの`universe`からasset indexを解決、ETH=1）。同一ID・同一本文の再送は**同じ`order_id`と`cloid`**を返し、本文相違は`IdempotencyConflict`、allowlist外は`AssetNotAllowed`、別principalは拒否 |

## 実装上の要点

- 認可は `funds_vault` の `session_status` に問い合わせ、**callerを信用せず**返却principalと比較する。取引口座IDはvaultの`get_trading_account`から取得し、所有権確認を兼ねる。
- asset indexは`meta_cache`から解決し、未取得は`PolicyUnavailable`（fail-closed）。固定値を埋め込まない。
- 受付fingerprintは`hl_sign::keccak256`（暗号学的ハッシュ）。
- 数量・価格は`hl_types::decimal`で検証し、Marketはスリッページ上限付きIOC指値のため価格必須、レバレッジ上限は5。

## レビュー指摘の修正（P3）

asset indexの解決が `"local"`／`"hyperliquid"` 固定だった点を修正し、`core_config`（v4）に
保存したnetwork・dexから解決するようにした。未設定は `PolicyUnavailable` で拒否する
（固定値を埋め込まない）。PocketICで「設定前はfail-closed、設定後に受付」を検証している。

## 所見：個人向け読み取りはqueryにできない

認可に `funds_vault` へのinter-canister呼び出しが必要だが、**queryは他Canisterを呼べない**ため、
`list_orders`（および今後の`get_account_snapshot`・`list_fills`）は現状updateで提供している。
最終設計では (a) 個人向け読み取りをupdateのまま提供する、(b) vaultからセッション写像をcoreへ
同期してqueryで返す、のいずれかを選ぶ必要がある（`docs/phase-0/api-contract.md` 3節のquery指定と
矛盾するため、契約側の見直し候補）。

## 申し送り：`get_account_snapshot` 実装に必要なAPI（実測）

- `auth::VerifiedSession` のフィールドは **`user_id` と `session_id` の2つだけ**。vaultで残高を引く際は
  `auth::session_status(&session)` の `user_id` と `session.session_id` から構築できる（`principal`・
  `revocation_generation` は存在しない）。
- 残高は `db::repo::ledger::user_balances(connection, user_id) -> UserBalances`、または
  `signed_balance(connection, &ledger::user_trading(&user_id))`（`balance(...)` は存在しない）。
- `ActionState` は `api_types::fund::ActionState`（`api_types::order` には無い）。
- 汎用のvault呼び出しヘルパは `serde` 依存と `CandidType + DeserializeOwned` の境界が必要になる。
  `get_account_snapshot` のように**戻り値の型が1つ**なら、`.candid()` をその型で受ける形にして
  ヘルパを作らない方が依存を増やさない。
