# P1-008 evidence: trading_core authorization and order admission

- Date: 2026-09-19 (last updated 2026-09-21)
- Scope: `crates/trading-core/src/lib.rs`, `crates/db/src/repo/{core_config,core_requests,meta,orders}.rs`
- Check: `bash scripts/pocket-ic-test.sh --test core_auth --test core_orders` (**12 passes**: one core_auth and 11 core_orders)

## Checks performed

| Test | Behavior |
|---|---|
| `core_auth.rs` | Controllers set vault principal; `whoami` verifies through vault `session_status` and returns user ID only when returned principal matches caller. Reject other principals, revoked sessions, and noncontroller configuration |
| `core_orders.rs` | Admit authorized orders with asset index resolved from meta `universe` (ETH=1). Same ID/body returns **the same order_id and cloid**; changed body yields `IdempotencyConflict`, disallowed assets `AssetNotAllowed`, and other principals are rejected |

## Implementation details

- Ask `funds_vault.session_status` for authorization and compare the returned principal rather than trusting caller claims. Obtain the trading account ID from vault `get_trading_account`, also checking ownership.
- Resolve asset indices from `meta_cache`; missing data yields `PolicyUnavailable` (fail closed). Do not hardcode indices.
- Admission fingerprints use cryptographic `hl_sign::keccak256`.
- Validate quantity/price through `hl_types::decimal`. Market orders are slippage-limited IOC limit orders and require price. Maximum leverage is five.

## P3 review fix

Replaced hardcoded `"local"` / `"hyperliquid"` asset-index lookup with network/dex from `core_config` v4. Missing configuration yields `PolicyUnavailable` rather than fixed defaults. PocketIC verifies fail-closed admission before configuration and success after configuration.

## Finding: personal reads cannot be ordinary queries

Authorization requires an inter-canister `funds_vault` call, but **ordinary queries cannot call other canisters**, so `list_orders` and subsequent `get_account_snapshot`/`list_fills` are updates. Final design must choose updates or synchronization of vault session mappings into core for queries. This conflicts with query declarations in `docs/phase-0/api-contract.md` section 3 and is a contract-revision candidate.

## Measured API notes for get_account_snapshot

- `auth::VerifiedSession` has only **user_id and session_id**. Build it from `auth::session_status(&session).user_id` and `session.session_id`; no `principal` or `revocation_generation` fields exist.
- Balances use `db::repo::ledger::user_balances(connection, user_id) -> UserBalances` or `signed_balance(connection, &ledger::user_trading(&user_id))`; no `balance(...)` exists.
- `ActionState` is in `api_types::fund`, not `api_types::order`.
- A generic vault-call helper needs serde and `CandidType + DeserializeOwned`. For a single return type such as `get_account_snapshot`, receive `.candid()` as that type instead of adding a helper/dependency.
