## 実装上の要点

- `dispatching` は**POST発行前に**CASで永続化する。署名とpayloadは`mark_signed`で**同じUPDATE**で書く（`fund_actions`のCHECKが「`signing`では署名NULL」「`signed`以降は署名とpayload必須」を要求するため、2段階に分けると制約違反になる）。
- outcallは非replicated。`max_response_bytes`は生の本文+ヘッダから見積もる（8 KiB）。応答が解釈できない場合は「未実行」と扱わず`unknown`へ進める。
- 払出し先（ユーザー別取引口座）は`derivation_path`からtECDSAで導出し、公開アドレスを`custody_accounts`へ保存する。
- PocketICのoutcall mockは`subnet_id`+`request_id`指定であり、テストヘルパ（`call_with_mocked_outcall`）が `submit_call → tick → get_canister_http → mock → await_call` を駆動する。

### 判明（修正済み）：出金の受付がactionを作っていない

払出しの送信試験を書いたところ、`request_withdrawal` の受付は**予約は作るが`fund_actions`の行を作らない**ため、
sweepが処理対象を見つけられず（processed=0）送信に至らないことが分かった。配分では受付時に
`provision_trading_account`＋`insert_fund_action`（nonceは`allocate_master_nonce("reserve")`）を行っているので、
出金にも同じ処理（destinationはEOAのHL口座、`kind="withdrawal"`、`signer_id="reserve"`）を追加した。**修正済み**。

### 判明（修正済み）：払出しの消込と台帳の整合

出金受付のaction作成と払出し送信を実装すると、送信→`payout_settled`までは到達するが、
その後の `get_fund_status` が **`BadRequest(MalformedPayload "liability balance is negative")`** を返した。
受付時の `reserve_funds`（`user_reserve`→`user_reserved_for_withdrawal`）と `payout_settled` の
仕訳が噛み合っていないためだった。次のとおり修正し、払出し試験（受理・拒否・不明）が通ることを確認した。**修正済み**。

1. `payout_settled` の仕訳で、受付時の予約（`user_reserved_for_withdrawal`）を**一度だけ消費**する。
2. `reserve_funds`／`consume_reservation`／`payout_settled` の責務を整理し、二重計上を防ぐ。
3. そのうえで払出し試験（受理・拒否・不明）を通す。

（コミット`97ae049`。出金予約は台帳側でも拘束されるため、`user_balances`と`fund_status_with_holds`が
reservations表のheldを重ねて引かないよう、拘束を1箇所に寄せた。）
