## Implementation details

- Persist `dispatching` through CAS **before POST**. `mark_signed` writes signature and payload in **one UPDATE** because CHECK constraints require NULL signature during `signing` and both signature/payload from `signed` onward; splitting updates violates the constraint.
- Outcalls are nonreplicated. Estimate `max_response_bytes` from raw body plus headers (8 KiB). Unparseable replies become `unknown`, not not-executed.
- Derive payout destinations (per-user trading accounts) through tECDSA derivation paths and store public addresses in `custody_accounts`.
- PocketIC mocks specify `subnet_id` and `request_id`; `call_with_mocked_outcall` drives `submit_call → tick → get_canister_http → mock → await_call`.

## Implemented and checked withdrawal dispatch branch

Added withdrawal dispatch in `outbox::dispatch`: reserve master `usdSend` signing→persist `dispatching`→nonreplicated send→`payout_settled` plus settled request on acceptance, reservation release on rejection, and `unknown` on uncertainty. Dedicated tests pass: `a_withdrawal_is_dispatched_from_the_reserve` checks admission through settlement; `payout_rejection_and_unknown_are_handled` checks rejection release/reversal and unknown retention. **All nine vault_outbox.rs tests pass.**

### Fixed finding: withdrawal admission did not create an action

Dispatch tests showed `request_withdrawal` created reservations but **no fund_actions row**, so sweeps processed zero actions. Allocation already used `provision_trading_account` and `insert_fund_action` with `allocate_master_nonce("reserve")`. Added equivalent withdrawal processing with the EOA's HL account destination, `kind="withdrawal"`, and `signer_id="reserve"`. **Fixed.**

### Fixed finding: payout settlement and ledger consistency

After action creation and dispatch, `payout_settled` succeeded but `get_fund_status` returned **`BadRequest(MalformedPayload "liability balance is negative")`**. Admission `reserve_funds` (`user_reserve`→`user_reserved_for_withdrawal`) and payout postings were inconsistent. Fixed and verified accepted/rejected/unknown payouts:

1. Consume the admission `user_reserved_for_withdrawal` reservation **once** in `payout_settled`.
2. Clarify `reserve_funds`, `consume_reservation`, and `payout_settled` responsibilities to prevent duplicates.
3. Pass accepted, rejected, and unknown payout tests.

Commit `97ae049`: ledger-side withdrawal holds mean `user_balances` and `fund_status_with_holds` must not subtract reservations-table holds again. Holds are consolidated in one place.
