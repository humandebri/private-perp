## 実行済みの検証

| 試験 | 内容 |
|---|---|
| `allocation_without_funds_is_rejected` | 残高0での配分要求を `InsufficientFunds` で拒否 |
| `allocation_is_idempotent_and_bounded_by_the_balance` | 予約の成立、同一要求の再送で二重予約しない、本文相違は `IdempotencyConflict`、予約が出金可能額から差し引かれる、残高超過の拒否 |
| `withdrawal_requires_a_valid_intent_signature` | 別鍵・宛先相違・期限切れの出金intentを拒否し、正しい署名のみ受付ける |
| `a_session_from_another_caller_is_rejected` | 他callerがセッションを使うと `Unauthenticated` |

## 設計上の決定

- 出金intentは `PrivatePerpWithdrawal(address eoa,uint64 amount,string asset,string destination,string network,uint64 nonce,uint64 expiresAt,bytes canister)`。クライアントが知り得ない内部ID（user_id・account_id）を署名対象に含めない。
- 送信するactionはwire payloadの構築時（署名段階）に作るため、`FundRequestAccepted.fund_action_id` は `Option`。
- テスト専用の入金計上（`test_credit_deposit`）は `test-venue` featureでのみコンパイルされ、本番ビルドには存在しない。

## 搬送路（replicated `/info`）の実装メモ（実測）

- `HttpRequest::with_transform(TransformContext)` が使える。`TransformContext` は
  `ic_cdk_management_canister::transform_context_from_query(method_name, context)` で組み立てる。
- **変換関数の戻り値型は `ic_cdk_management_canister::HttpRequestResult`**（`HttpResponse` は0.10系に存在しない）。
  シグネチャは**完全修飾**で書く（`fn transform_info(args: ic_cdk_management_canister::TransformArgs)
  -> ic_cdk_management_canister::HttpRequestResult`）。そうしないと `export_candid!` が生成する
  lib.rs 側で型名が解決できずコンパイルエラーになる。
- 入金は `/info` の `userNonFundingLedgerUpdates`（`{time, hash, delta:{usdc}}`）で取得し、
  変換では `hash`・`time`・`delta.usdc` だけを残して決定論化する。金額は十進→マイクロの整数変換で扱う。
