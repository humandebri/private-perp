# P1-007 evidence: HPKE (RFC 9180) dependency feasibility

- Date: 2026-09-19
- Scope: `crates/funds-vault/src/hpke.rs`, `Cargo.toml` workspace dependencies
- Goal: before implementation, check that the `Plan.md` 16.5 suite (RFC 9180 HPKE X25519 / HKDF-SHA256 / ChaCha20-Poly1305) works in wasm32 canisters.

## Results

- Selected `hpke = "=0.14.1"` with `alloc`, `x25519`, and `chacha` features.
- **Do not enable `getrandom`**: canisters have no OS randomness. Supply `raw_rand` output as IKM and derive keys with `X25519HkdfSha256::derive_keypair`.
- `cargo build --release --target wasm32-unknown-unknown -p funds-vault` succeeded, confirming HPKE types and derivation compile for wasm32. Use an implementation with an audit history rather than implementing primitives from scratch.
- Initially specified `chacha20poly1305`, `hkdf`, and `sha2` feature names. Correct 0.14.1 features are `chacha` (ChaCha20-Poly1305) and `x25519` (including HKDF-SHA256).

## Key-registry checks performed

`bash scripts/pocket-ic-test.sh --test vault_hpke` (one pass): fail closed without a generated public key; controllers can generate keys; keys are stable within a generation and updates advance generation (`hpke_keys` v6). Private keys stay in the canister DB and are not exposed by public APIs.

## Round-trip checks performed

`bash scripts/pocket-ic-test.sh --test hpke_roundtrip` (one pass): a deterministic RNG implementing `rand_core 0.10.1` `TryRng` (`Error = Infallible`) and `TryCryptoRng` encrypts with `single_shot_seal_with_rng`; `single_shot_open` decrypts to matching plaintext. **Changing `aad` fails decryption**, demonstrating binding; identical IKM deterministically derives identical key pairs. Implementing `TryRng` resolved the initial rand_core 0.10 API mismatch. The `single_shot` module is private; use functions from the crate root.

## Canister envelope checks performed

`bash scripts/pocket-ic-test.sh --test vault_hpke_envelope` (one pass): create an envelope with the current canister key and a deterministic RNG seeded by `raw_rand`. It decrypts with the same caller/deadline and **fails for a different caller or deadline**. AAD binds network, canister, method, caller, request ID, and deadline. Envelopes differ on each call, demonstrating randomness.

## Unverified work for the next round

- Envelopes for actual personal-data APIs (orders/snapshots), encrypted responses, and key rotation (T-605).
- Until implemented and tested, this establishes dependency feasibility only; confidentiality verification remains incomplete.
