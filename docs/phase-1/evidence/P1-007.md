# P1-007 証跡：HPKE（RFC 9180）の依存成立確認

- 日付：2026-09-19
- 対象：`crates/funds-vault/src/hpke.rs`、`Cargo.toml`（workspace依存）
- 目的：`Plan.md` 16.5の方式（RFC 9180 HPKE X25519 / HKDF-SHA256 / ChaCha20-Poly1305）を
  canister（wasm32）で使えるかを、実装前に確認する。

## 結果

- 採用：`hpke = "=0.14.1"`、featureは `alloc`・`x25519`・`chacha`。
- **`getrandom` を有効にしない**（canisterにはOS乱数が無い）。鍵は `raw_rand` の入力を
  IKMとして与え、`X25519HkdfSha256::derive_keypair` で導出する。
- `cargo build --release --target wasm32-unknown-unknown -p funds-vault` が成功し、
  HPKEの型と鍵導出がwasm32でコンパイルできることを確認した（監査実績のある実装を使い、
  プリミティブは自作しない）。
- 当初 `chacha20poly1305`・`hkdf`・`sha2` というfeature名を指定していたが、0.14.1の
  正しいfeatureは `chacha`（ChaCha20-Poly1305）と `x25519`（HKDF-SHA256を含む）である。

## 実行済みの検証（鍵レジストリ）

`bash scripts/pocket-ic-test.sh --test vault_hpke`（1件成功）:
未生成では公開鍵を返さない（fail-closed）、controllerが生成でき、同じ世代では公開鍵が安定し、
更新で世代が進む（`hpke_keys` v6）。秘密鍵はcanister内のDBに留め、公開APIへ出さない。

## 実行済みの検証（往復）

`bash scripts/pocket-ic-test.sh --test hpke_roundtrip`（1件成功）:
`rand_core 0.10.1` の `TryRng`（`Error = Infallible`）+ `TryCryptoRng` を実装した決定的RNGで
`single_shot_seal_with_rng` により暗号化し、`single_shot_open` で復号して一致することを確認した。
**`aad`を変えると復号に失敗**すること（束縛が効くこと）と、同じIKMから同じ鍵対が
決定的に導出できることも確認した。当初`rand_core 0.10`のAPI変更で詰まっていた点は、
`TryRng`実装で解決した（`single_shot`モジュールは非公開で、関数はcrate rootから使う）。

## 実行済みの検証（canister側の封筒）

`bash scripts/pocket-ic-test.sh --test vault_hpke_envelope`（1件成功）:
canisterの現行鍵で封筒を作り（乱数は`raw_rand`を種にした決定的RNG）、同じ呼び出し元・
同じ期限では復号でき、**期限または呼び出し元が違うと復号に失敗**することを確認した
（`aad`がnetwork・canister・method・caller・request_id・期限を束縛）。
封筒は呼び出しごとに異なる（乱数が効いている）。

## 未検証（次ラウンド）

- これらを実装して試験するまで、HPKEは「依存が成立した」段階であり、機密性の検証は未了である。
