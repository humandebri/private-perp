# P1-005 証跡：ローカルECDSAスパイク（結果＝ブロッカー）

- 日付：2026-09-19
- 目的：`Implementation.md` 1-2・9.1の4（閾値ECDSAの署名と `v` 復元）をローカルで確認する
- 対象：`crates/funds-vault/src/crypto.rs`、`crates/pocket-ic-tests/tests/ecdsa_spike.rs`

## 実行

```sh
bash scripts/pocket-ic-test.sh --test ecdsa_spike -- --nocapture
```

結果：`test result: ok. 1 passed`（公開鍵は圧縮SEC1、署名は公開鍵のアドレスへ復元、同じseedは同じ鍵）。

## 判明した事実（ブロッカー）

- PocketIC 16.0.0の既定トポロジには閾値ECDSAの鍵が存在しない。`ecdsa_public_key` は
  `ChainKeyError("Requested unknown threshold key: ecdsa:Secp256k1:test_key_1, existing keys: []")`
  で拒否する（`test_key_1`／`dfx_test_key` のいずれも同様）。
- `pocket-ic 16.0.0` crateはsubnetのECDSA設定（鍵の装着）を公開しておらず、サーバ起動引数で
  指定する経路も無い。したがって**ローカルでは実tECDSAを検証できない**。

## 対応（計画のフォールバック規則どおり）

- `test-venue` featureでのみ有効な**決定的テスト署名器**へフォールバックする（derivation pathの
  Keccakから鍵を導出）。本番ビルド（feature無し）は管理Canisterの `sign_with_ecdsa` のみを使い、
  フォールバックは存在しない。
- 実tECDSA（`sign_with_ecdsa` の受理、署名時間、キュー溢れ、`cost_sign_with_ecdsa`）の検証は
  **testnetへ繰り延べ、未達として扱う**。ローカルの計測値（往復10.8ms、テスト署名器）は
  実tECDSAの性能値ではない。
