# P1-005 証跡：ローカルECDSAスパイク（閾値ECDSAが動作）

- 日付：2026-09-19
- 目的：`Implementation.md` 1-2・9.1の4（閾値ECDSAの鍵導出・署名・`v` 復元）をローカルで確認する
- 対象：`crates/pocket-ic-tests/src/lib.rs`（トポロジ）、`crates/pocket-ic-tests/tests/ecdsa_spike.rs`、`crates/funds-vault/src/crypto.rs`

## 結論

**ローカルで実tECDSA（`test_key_1`）が動作する。** 当初「PocketICには閾値ECDSA鍵が無い」と記録したが、これは誤りで、
**既定トポロジ（`PocketIc::new()`）に鍵サブネットが無いだけ**だった。`PocketIcBuilder::new()
.with_application_subnet().with_test_threshold_keys_subnet().build()` とすることで鍵が提供される。

Key idは `test_key_1` で動作した（`docs/phase-0/environments.md` に記録）。

## 実行

```sh
bash scripts/pocket-ic-test.sh --test ecdsa_spike -- --nocapture
```

結果：`test result: ok. 1 passed`

- 得られた公開鍵は圧縮SEC1（33バイト、先頭02/03）。
- 署名（r‖s、閾値署名に`v`は含まれない）から `v` を候補復元し、公開鍵のアドレスへ復元できる。
- 同じderivation pathは同じ公開鍵になる（導出が決定的）。
- 得られた鍵は決定的テスト鍵とは異なる（＝テスト署名器ではなく実tECDSA）。
- PocketIC上の往復時間は約17.9ms（**PocketICの参考値であり、testnetや本番subnetの性能値ではない**）。

## 残る未検証（testnetへ繰り延べ）

`sign_with_ecdsa` のp50/p95、キュー溢れ、`cost_sign_with_ecdsa` の実測、Confidential Subnetからの
到達性は、PocketICでは本番同等にならないため testnet で確認する（未達として扱う）。

## この結論の訂正について

`crates/funds-vault/src/crypto.rs` に入れていたテスト署名器フォールバックは不要になったため削除した。
`scripts/check-signing-boundary.sh` の例外も削除し、canisterクレートでの生鍵署名は再び全面禁止である。
