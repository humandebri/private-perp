# P1-005 evidence: local threshold ECDSA spike

- Date: 2026-09-19
- Goal: locally verify `Implementation.md` 1-2 and 9.1 item 4 (threshold ECDSA derivation, signing, and `v` recovery)
- Scope: `crates/pocket-ic-tests/src/lib.rs` (topology), `crates/pocket-ic-tests/tests/ecdsa_spike.rs`, `crates/funds-vault/src/crypto.rs`

## Conclusion

**Real local tECDSA (`test_key_1`) works.** The initial statement that PocketIC has no threshold ECDSA keys was incorrect: **the default topology (`PocketIc::new()`) lacks a key subnet**. Keys are available using `PocketIcBuilder::new().with_application_subnet().with_test_threshold_keys_subnet().build()`.

Key ID `test_key_1` worked, as recorded in `docs/phase-0/environments.md`.

## Execution

```sh
bash scripts/pocket-ic-test.sh --test ecdsa_spike -- --nocapture
```

Result: `test result: ok. 1 passed`

- Public key: compressed SEC1, 33 bytes, prefix 02/03.
- Candidate recovery of `v` from the r‖s signature (threshold signatures omit `v`) recovers the public key's address.
- Identical derivation paths produce identical public keys (deterministic derivation).
- The resulting key differs from the deterministic test key, establishing real tECDSA rather than the test signer.
- PocketIC round trip was about 17.9 ms (**a PocketIC reference value, not testnet or production subnet performance**).
