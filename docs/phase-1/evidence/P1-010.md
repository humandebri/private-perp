## Resolved design inconsistency: agent key ownership

The following records the state before resolution (before 2026-09-20). The **vault** derived/stored agent keys (`agent_generations.agent_address` from vault tECDSA) and master-signed `approveAgent`. `Implementation.md` section 7 instead assigned per-account/per-generation agent derivation/storage to core and approval of that address to vault. Core also explicitly prohibited requesting arbitrary digest signatures from vault.

With keys only in vault, core could not sign orders. Options:

1. **Recommended:** core derives/stores agent keys; vault `approve_agent_generation` **receives a 20-byte agent address** and master-signs approval without seeing orders.
2. Vault offers order-payload signing, conflicting with the arbitrary-digest prohibition in authority-matrix section 5; limiting it to vault-verifiable amounts, markets, and destinations would blur responsibilities.

**Adopted option 1 on 2026-09-20:**

- `trading_core` derives/stores agent keys in core `agent_generations` v4 through `request_agent_generation` / `get_agent_status`.
- `funds_vault.approve_agent_generation` approves the **provided 20-byte address** with the master key and activates records only on acceptance. PocketIC checks acceptance and rejection.

Removed duplicate vault `request_agent_generation` / `get_agent_status` derivation paths. Only trading_core now derives/stores agent keys. Next work: agent-signed orders, nonreplicated dispatch, and orderStatus reconciliation.
