# 市場観測とHTTP outcall v2

2026-09-29の指定に合わせ、すべてのHL HTTPS outcallを `HttpRequest::new(...).non_replicated()` に統一した。採用中の `ic-cdk-management-canister 0.2.0` のbuilderは `pricing_version=Some(2)` を設定し、`non_replicated()` が `is_replicated=Some(false)` を設定する。

対象は注文・取消・Agent承認・送金の `/exchange` と、市場・口座・約定・注文状態・入出金履歴の `/info`。外部通信は一つのICノードから行う。従来の複数ノード間の応答合意は採用しない。単一ノードの応答の真正性をtransformだけで証明することはできず、HLと選択されたノードへの信頼を含む方式である。

## 入力検証

市場transformは引き続きCanisterが固定した対象銘柄・閾値・要求開始時刻で検証する。これは単一応答の検証であり、ノード間合意ではない。

- metadata: 銘柄の一意性、配列の対応、上場廃止フラグ、登録index、最低出来高。
- order book: 銘柄、要求開始から前後60秒以内の時刻、両側1〜20段、正の価格・数量、整列、非交差、最大スプレッド、最低板厚。
- HTTP失敗・欠損・不正JSONは受付を許可しない。応答サイズ上限、共有REST予算、署名前後の状態再検証は維持する。

BTC/ETHの観測は一括保存する。取得中に閾値が変わった場合や、観測が別の実行に置き換わった場合は保存を拒否する。市場情報は操作時に必要なら取得し、5分以内の観測を再利用する。10分の失効条件と口座状態の10秒鮮度条件を維持する。

## 待機と再開

全口座の定期入金巡回と定期市場取得を廃止した。`vault_private_call(confirm_deposit)` は認証済みユーザーが共通保管口座の履歴を1ページ取得する操作で、第三者の計上件数は返さない。入金の帰属・重複排除はHL履歴と既存の仕訳処理が判断する。

DB更新がワーカーを起こす。資金要求・送信結果・フェンス解除・注文・建玉などが残る間だけ5秒間隔の直列ワーカーを維持し、未完了処理がなくなれば解除する。配分済み資金は、未着金の対象口座だけ照合する。送金の結果が不明な場合は再送せず停止する。所有者の世代付き手動許可で一度だけ照合し、未確定なら再び停止する。実行許可は業務状態とは別の永続テーブルで管理する。

起動・アップグレード時はDBを調べ、未完了処理がある場合だけ再開する。送信journalの復旧ロックは維持する。CDK 1.0の直列timerは実行中に自身を解除できないため、次のメッセージで未完了処理を再確認して解除する。

UIの「入金を確認」「取引情報を確認」で明示的に更新する。新規注文のバックエンドも必要な観測を取得してから既存のリスク判定へ進む。ブラウザーを閉じても正常な建玉・注文監視は継続する。失敗した処理は手動再開を待つ。詳細と対応範囲は[手動再試行](manual-retry-plan.md)を参照。ICの保存費用やユーザー操作の実行費用は残る。

## 検証

`scripts/test-single-canister.sh` は本番・mock両Wasmの契約と入力検証を確認する。本番Wasmでは入金確認の認可・重複計上防止、保管残高のみの待機、配分要求での再開、対象口座の着金確認、建玉監視と終了、結果不明POSTの再送防止を検証する。発行されたHTTPリクエストの `NonReplicated` も検査する。

ローカル比較では、旧公開Wasmの10分待機が約11.40B cycles、新方式の同一fixtureが約0.089B cycles。後者は初回停止処理を含む。実ネットワークの請求額を復元した数字ではない。公開デプロイと実HLの資金往復は未実施であり、[受入記録](testnet-acceptance.md)で区別する。

参照: [ICP HTTPS outcall modes](https://docs.internetcomputer.org/concepts/https-outcalls/)、[HTTPS outcall security](https://docs.internetcomputer.org/guides/security/https-outcalls/)。
